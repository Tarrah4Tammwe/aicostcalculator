How an estimate is built.

The calculator applies published list prices to a workload you describe. It does not call a provider, sample a model, or forecast quality. Two models with the same monthly figure can still be the wrong pair for a product. This page is only the billing math.

Formula

input tokens = requests × input tokens per request
output tokens = requests × output tokens per request
cached tokens = input tokens × cache share
fresh tokens = input tokens − cached tokens
cost = fresh / 1,000,000 × input rate
     + cached / 1,000,000 × cache-read rate
     + output / 1,000,000 × output rate

The year figure is the month times twelve. It assumes the same volume every month. Per request is the month divided by the request count.

Rates are chosen in this order. Start with the model's short-context price. If you turn on long context and that model publishes a higher tier, replace the three rates with the long-context rates. If you choose batch and the provider publishes a 50% batch price, halve the rates in use. Cache share then splits input between the input rate and the cache-read rate.

What is included

  • Standard text input, cache reads, and text output for the 15 models on the rate card.
  • A 50% batch factor for OpenAI, Anthropic, and Google, matching their published batch columns.
  • Long-context replacement rates for GPT-6, Gemini 3.1 Pro, and the three Grok rows.
  • DeepSeek at the published peak rate. Off-peak is half, and the interface says so.

What is excluded

  • Cache writes. They are real, and they are billed once per stored prefix, so a monthly volume model cannot see them from a single slider.
  • Tool, search, and retrieval fees charged per call.
  • Image, audio, and video token prices. Gemini Flash-Lite in the table is the text, image, and video input rate.
  • Regional and data-residency uplifts, priority or fast mode, and provisioned throughput.
  • Taxes, committed-spend discounts, and free-tier quotas.
  • Retries and extra agent steps you did not put in the request count.

Rounding and display

The calculation uses the full rate, then the screen rounds money for reading. Amounts of at least one dollar show two decimal places. Amounts under one cent can show up to six. The copied estimate uses the same rounding as the screen. Ranking uses the unrounded total, so two models that display as the same dollar can still have a stable order.

How rates are chosen

A model stays on the card when its price is on the provider's own pricing page or launch note, and when it is a current way to buy that tier. Superseded rows such as GPT-4o and Claude Opus 5 are described in prose on the rate card and left out of the estimator, so a default selection cannot quietly use a retired price. Gemini 3.1 Pro remains because Google still publishes a paid rate for the preview model, and the row is labeled preview.

Cache-read prices for Claude Haiku 4.5, Sonnet 5, and Fable 5.1 follow Anthropic's published rule: 10% of the input price, and 2.5% for Fable 5.1. Opus 5.5 uses the explicit cache-read price on its launch page, $0.20, which is tighter than 10% of $4. Where a page gives an explicit number, the explicit number wins.

Corrections

List prices move. The check date on each page is the date the source pages were read for that revision, not a promise that a provider has stood still since. If a figure here disagrees with the provider page, the provider page is the one to budget from. Send the model name, the figure, and the source link through the contact page and the card will be updated.
