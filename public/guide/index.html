A field guide for the bill

How AI API pricing works.

Providers bill by the token. A token is a slice of text, often shorter than a word in English and longer than a word in some other languages. The price of a request is the price of the tokens you send plus the price of the tokens the model writes back. This page is the vocabulary the calculator assumes. The numbers it uses are on the rate card.

Input and output are different products

Input tokens are the prompt: instructions, the user message, retrieved passages, and prior turns you choose to resend. Output tokens are what the model generates. Reading is cheaper than writing on every model in the card. GPT-6 Sol charges $2 to read a million tokens and $10 to write a million. Claude Opus 5.5 charges $4 and $20. Grok 4.3 is closer, at $1.25 and $2.50, which is why a writing-heavy workload can reorder the ranking even when input prices look similar.

A rough English planning figure is about three quarters of a word per token, but tokenizers differ. When a budget matters, measure a real sample with the provider's tokenizer instead of converting from word count.

A worked month

Take a coding agent: 8,000 requests in a month, 6,000 input tokens each, 1,800 output tokens each. That is 48 million input tokens and 14.4 million output tokens.

48 × $2 + 14.4 × $10 = $96 + $144 = $240 on GPT-6 Sol

The same volume on Claude Sonnet 5 is the same $240, because Sonnet 5 is also $2 and $10. On Grok 4.3 it is 48 × $1.25 plus 14.4 × $2.50, or $96. On GPT-6 Luna it is 48 × $0.10 plus 14.4 × $0.50, or $12. The spread is the point of comparing a workload instead of comparing a single sticker price. You can load this example from the coding-agent preset in the calculator.

Prompt caching

Agents and retrieval systems repeat a large prefix: a system prompt, tool definitions, or a standing style guide. Caching stores that prefix and bills later requests at a read rate. On Sol the read rate is $0.20, one tenth of the input rate. On Opus 5.5 it is $0.20 against a $4 input rate. On Luna it is $0.01.

If 80% of the coding agent's 48 million input tokens are cache reads, Sol's input line falls from $96 to 9.6 × $2 plus 38.4 × $0.20, or $26.88. Output is unchanged at $144. Cache reads do not discount what the model writes.

The first request that stores the prefix pays a cache-write fee. OpenAI lists cache writes at 1.25 times the input rate (Luna $0.125, Sol $2.50, Astra $12.50 per million). Anthropic's Opus 5.5 launch page lists cache writes at $5 per million. The monthly estimate on this site leaves writes out, because a prefix that changes every request never earns the read discount, and a stable prefix is written rarely. Count writes when you are designing the cache, then use the calculator for the steady state.

Batch and other slower tiers

Batch is for work that can wait. OpenAI prices batch and flex at half of standard, on both the short-context and long-context columns. Anthropic's batch API is half off the base token price. Google lists a batch tier at half the standard token price for Gemini 3.5 Flash, 3.1 Flash-Lite, and 3.1 Pro.

xAI's current pricing page does not publish a batch price for Grok 4.3, Grok 4.6, or Grok Build 0.1. Selecting batch in the calculator leaves those models on the standard rate and says so.

DeepSeek's discount is the clock. Peak hours are 01:00–04:00 and 06:00–10:00 UTC on weekdays, excluding Chinese public holidays. All other hours are off-peak at half price. The calculator uses peak so a budget is not built on the cheaper window by accident. If your traffic is weekends and overnight outside those bands, halve the DeepSeek result.

Long context is a cliff, not a slope

Several providers keep a low rate up to a threshold and then reprice every token in the request. OpenAI's line is 272,000 input tokens. Past it, GPT-6 input and cache rates double and output rises by half: Sol goes from $2 / $10 to $4 / $15. Gemini 3.1 Pro steps from $2 / $12 to $4 / $18 above 200,000 prompt tokens. Grok models double at 200,000 prompt tokens.

One oversized prompt in a batch of short ones should be priced on its own. Averaging tokens hides the cliff. Claude's models on this card, and Gemini's Flash models, publish a single rate across the window, so the cliff does not apply to them.

Thinking tokens

Some models reason in hidden tokens before the answer you see. Google's Gemini price sheet bills those thinking tokens as output. A 200-token answer with 2,000 thinking tokens is a 2,200-token output for the invoice. If you only type the visible length into the calculator, the Gemini rows will read low. OpenAI and Anthropic also spend extra tokens on reasoning for some models; put the billed output, not the visible answer, in the output field.

What a list price leaves out

  • Tool calls, web search, and file search, which several providers price per call on top of tokens.
  • Image, audio, and video tokens. Gemini Flash-Lite's audio input is twice the text rate used here.
  • Data-residency and regional endpoints. OpenAI charges a 10% uplift on eligible models released on or after 5 March 2026.
  • Retries, validator loops, and agent steps that multiply one user action into many requests.
  • Priority or fast modes, which OpenAI prices at twice the applicable rate.

Treat the calculator as the token floor. Add the extras from the provider's own page before you commit a budget. If a rate on this site has drifted, the contact page is the correction path, and the methodology records what the formula includes.
